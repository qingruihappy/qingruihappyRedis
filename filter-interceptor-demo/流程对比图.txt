│                            异常处理机制对比                                   │
└─────────────────────────────────────────────────────────────────────────────┘

╔════════════════════════════════════════════════════════════════════════════╗
║                            Filter 异常处理                                  ║
╠════════════════════════════════════════════════════════════════════════════╣
║  特点：                                                                     ║
║  • 必须显式 try-catch，否则异常向上传播到Servlet容器                        ║
║  • 捕获异常后可以自定义错误响应                                             ║
║  • 如果不捕获，会中断整个请求处理链                                         ║
║  • 后置处理不会执行（除非在finally中）                                      ║
║                                                                             ║
║  代码示例：                                                                 ║
║    try {                                                                    ║
║        chain.doFilter(request, response);                                   ║
║        // 后置处理（如果上面抛异常，这里不执行）                            ║
║    } catch (Exception e) {                                                  ║
║        // 异常处理                                                          ║
║        response.setStatus(500);                                             ║
║    }                                                                        ║
║                                                                             ║
║  影响范围：                                                                 ║
║  • 中断所有后续Filter                                                       ║
║  • 中断DispatcherServlet                                                    ║
║  • 中断所有Interceptor                                                      ║
║  • 中断Controller                                                           ║
╚════════════════════════════════════════════════════════════════════════════╝

╔════════════════════════════════════════════════════════════════════════════╗
║                         Interceptor 异常处理                                ║
╠════════════════════════════════════════════════════════════════════════════╣
║  特点：                                                                     ║
║  • 不需要显式捕获，Spring会自动处理                                         ║
║  • afterCompletion总是会执行（对于已执行preHandle的）                       ║
║  • afterCompletion可以获取异常对象                                          ║
║  • Filter的后置处理仍然会正常执行                                           ║
║                                                                             ║
║  代码示例：                                                                 ║
║    public boolean preHandle(...) throws Exception {                         ║
║        if (条件) {                                                          ║
║            throw new Exception("业务异常");  // 可以直接抛                  ║
║        }                                                                    ║
║        return true;                                                         ║
║    }                                                                        ║
║                                                                             ║
║    public void afterCompletion(..., Exception ex) {                         ║
║        if (ex != null) {                                                    ║
║            // 处理异常，记录日志，清理资源                                  ║
║        }                                                                    ║
║    }                                                                        ║
║                                                                             ║
║  影响范围：                                                                 ║
║  • 中断后续Interceptor的preHandle                                          ║
║  • 中断Controller                                                           ║
║  • 中断所有Interceptor的postHandle                                         ║
║  • 但已执行preHandle的afterCompletion会执行                                ║
║  • Filter后置处理正常执行                                                   ║
╚════════════════════════════════════════════════════════════════════════════╝


┌─────────────────────────────────────────────────────────────────────────────┐
│                              记忆口诀                                         │
└─────────────────────────────────────────────────────────────────────────────┘

    Filter在外层，Interceptor在内层
    Filter像洋葱，一层包一层
    Interceptor有三段，pre顺post倒after倒
    
    异常要分清：
    • Filter抛异常，整个链中断
    • Interceptor抛异常，部分链继续
    
    资源要对称：
    • preHandle成功，afterCompletion必执行
    • postHandle执行，Controller必成功
    
    顺序要记牢：
    Filter → Dispatcher → Interceptor → Controller
