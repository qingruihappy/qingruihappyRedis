# 快速开始指南

## 1. 启动应用

```bash
cd /workspace/filter-interceptor-demo
mvn spring-boot:run
```

等待应用启动完成，看到以下日志表示启动成功：
```
Tomcat started on port(s): 8080 (http)
Started FilterInterceptorDemoApplication
```

**预期输出**（控制台）:

**响应**: `Filter捕获异常: SecondFilter 故意抛出的异常`

**注意**: ThirdFilter、DispatcherServlet、所有Interceptor、Controller都不会执行

---

#### 场景3: SecondInterceptor抛异常
```bash
curl "http://localhost:8080/test?throwInterceptorException=true"
```

**预期输出**（控制台）:
```
========== FirstFilter 前置处理 ==========
========== SecondFilter 前置处理 ==========
========== ThirdFilter 前置处理 ==========
---------- FirstInterceptor preHandle ----------
---------- SecondInterceptor preHandle ----------
---------- SecondInterceptor 抛出异常！----------
---------- FirstInterceptor afterCompletion (检测到异常: SecondInterceptor 故意抛出的异常) ----------
========== ThirdFilter 后置处理 ==========
========== SecondFilter 后置处理 ==========
========== FirstFilter 后置处理 ==========
```

**注意**: 
- 只有FirstInterceptor的afterCompletion执行（因为只有它成功执行了preHandle）
- 所有Filter的后置处理仍然执行
- Controller不会执行

## 5. 核心结论

### Filter异常处理
- ✅ 在Filter内部显式捕获异常
- ✅ 可以自定义错误响应
- ❌ 如果不捕获，会中断整个请求处理流程
- ❌ 后续所有组件（Filter、DispatcherServlet、Interceptor、Controller）都不会执行

### Interceptor异常处理
- ✅ 不需要显式捕获，Spring会自动处理
- ✅ afterCompletion会被调用（对于已执行preHandle的拦截器）
- ✅ afterCompletion可以获取异常对象进行处理
- ✅ Filter的后置处理仍然会执行
- ❌ postHandle不会执行（因为Controller未成功执行）

### 执行顺序记忆口诀
```
Filter像洋葱，一层包一层
Interceptor有三段，pre顺post倒after倒
异常要分清，Filter断Interceptor续
```

## 7. 常见问题

### Q: 为什么Filter异常时，FirstFilter的后置处理不执行？
A: 因为异常在catch块中被捕获并处理了，try块后面的代码（后置处理）不会执行。如果想让后置处理总是执行，应该使用try-finally结构。

### Q: 为什么Interceptor异常时，Filter的后置处理还会执行？
A: 因为Filter采用"洋葱模型"，即使DispatcherServlet内部抛异常，只要这个异常被DispatcherServlet处理了（不向外抛），Filter的后置代码仍会按照调用栈顺序执行。

### Q: 为什么SecondInterceptor抛异常后，只有FirstInterceptor的afterCompletion执行？
A: 这是Spring的设计：只有成功执行preHandle的拦截器，其afterCompletion才会被调用。这确保了资源准备和清理的对称性。

### Q: 生产环境中如何选择Filter还是Interceptor？
A: 
- **Filter**: 用于通用的请求处理（编码、跨域、安全过滤等），不依赖Spring上下文
- **Interceptor**: 用于业务相关的处理（权限校验、日志记录等），需要访问Spring Bean
